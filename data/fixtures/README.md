# 测试数据

回归只允许三家店，定义在 [shops.json](../shops.json)：

- B1 `UI货品回归店铺B1_20260831_01`（740，天猫）主店
- A1 `UI货品回归店铺A1_20260831_01`（738，天猫）隔离
- A2 `UI货品回归店铺A2_20260831_01`（739，拼多多）隔离

对不上名称或店铺 ID 立刻停。不要进儒意官方旗舰店或店铺 78。

## 文件

| 文件 | 用途 |
| --- | --- |
| [permanent.json](permanent.json) | 永久夹具：货品、商品、知识、变量、替换词。禁止删除。 |
| [ephemeral.json](ephemeral.json) | CRUD 用的 20 条临时批，前缀 `UIAUTO_CRUD_`，用完必须删干净。 |
| [auth.json](auth.json) | 授权授/撤/批量，对象只有这三家店。 |
| [talk-cases.json](talk-cases.json) | 测试窗对答，依赖永久夹具里的知识。 |
| [../b1/shared-fixtures.json](../b1/shared-fixtures.json) | 已有 B1 甲乙共享样本，在线只读断言仍读它，不要改识别码。 |

## 布置顺序（B1 已有历史数据则只巡检）

1. 登录开发站，选 B1。
2. 按 `permanent.json` 的 `shops.B1` 核对货品、商品、属性、分组、店铺/自定义/场景知识、变量、替换词（停用）、欢迎语和跟单草稿（未启用）。缺哪条补哪条，不要重建已存在的同名记录。
3. 切到 A1、A2，按 `shops.A1` / `shops.A2` 各建 1 货品 + 1 商品 + 1 条带店名识别码的店铺知识。商品 ID 若平台不允许本文占位值，在对应店内新建后把真实 ID 回写到 `permanent.json`。
4. 授权用测试员工账号（环境变量，不写进仓库），只对这三家店做授/撤。
5. 测试窗对话前跑 `talk-cases.json` 的 `preflight`。
6. CRUD 套件只用 `ephemeral.json` 的前缀；结束时按前缀搜索必须为 0。失败也要清这批。

## 禁止删除

`UIAUTO_20261020_STOCK01`、`UIAUTO_20261021_STOCK02`、商品 `9102026102001` / `9102026102101` / `9102026102102`。

品牌、店铺页面没有删除，不要为凑 CRUD 去新建真实店铺。授权「大量 20 条」不能理解成 20 家店，只对这 3 家反复授撤，20 条批量用店内业务数据。
