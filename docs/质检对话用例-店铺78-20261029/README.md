# 质检点五轮对话用例

对应店铺78前次新增的75个质检点。每点3组，共225组，每组5轮（买家、客服各一句为一轮）。

- `全部225组完整对话.md`：完整阅读版，包含所有对话、质检点判断标准、业务依据、主预期命中和关键触发轮。
- `全部225组对话.json`：结构化版本，包含用例ID、已保存质检点记录ID、`turns`及按顺序排列的10条`messages`。
- `01-*.md`至`15-*.md`：按15个分类拆分的阅读版，每份包含15组对话。
- `结构校验结果.json`：数量、覆盖范围、轮数、发言数及完全重复检查结果。
- `01-*.txt`至`15-*.txt`：逐条人工编写的对话原稿。
- `build_cases.py`：从原稿整理输出并校验结构的本地脚本。

JSON中的`business_context`是质检系统应知的后台事实，不是买家或客服曾经说过的话。涉及后台政策、执行状态或必要条件的案例，送检时应一并加载这些事实，否则应按证据不足处理，不能将预期命中当作实际结果。附件不可读案例为纯文本模拟；多模态执行需配套附件夹具。

所有业务资料及个人资料为合成测试数据；客服的错误行为是刻意构造的负面样例。本次仅设计和校验，没有写入后台对话，也没有执行实际质检。主目标以外的合理标签允许同时命中。
